# Правило публикации security.maybeso.me

## Доступ к исходным заметкам

- Источник истины для заметок и вложений — vault `content` в Ignis: `http://192.168.1.122:8081`. Читать актуальный контент через API, а не через Personal MCP, локальную копию Obsidian или старый checkout.
- Использовать пользовательскую авторизованную сессию: вход `POST /api/auth/login`, список хранилищ `GET /api/vault/list`, дерево `GET /api/fs/tree?vault=content`, чтение файла `GET /api/fs/readFile?vault=content&path=<URL-encoded path>`. Для текста можно передать `encoding=utf8`; вложения читать как байты.
- Cookie хранить во временном файле вне репозитория; не записывать логин, пароль, cookie или путь конкретной сессии в правила, Git и журналы. При истечении сессии запросить новую у пользователя.
- Локальный снимок из API используется только для подготовки и проверки сборки. Перед публикацией проверить, что исходные заметки не изменились. Изменения исходных заметок выполнять через Ignis API только в пределах поручения пользователя.
- Эти `AGENTS.md` и `WRITING-STYLE.md` сохранены локально в `my_ansible/playbook/second_brain/content-rules/`. В vault `content` на момент проверки этих файлов нет. Если там появятся дополнительные правила, прочитать их через API перед работой с соответствующими заметками.

## Повторная авторизация при HTTP 401

При ответе `401 Unauthorized` от Ignis сразу сообщить пользователю, что нужна новая сессия, и показать команду входа ниже. Попросить выполнить её в своём терминале и прислать только путь, напечатанный последней строкой. Не просить логин, пароль или содержимое cookie-файла. После получения пути проверить доступ через API и продолжить исходное поручение.

```sh
IGNIS_URL='http://192.168.1.122:8081'
IGNIS_COOKIE=$(mktemp)

# Логин и пароль вводятся скрыто и не попадают в историю команд.
python3 -c '
import getpass, json
print(json.dumps({
    "username": getpass.getpass("Логин: "),
    "password": getpass.getpass("Пароль: ")
}))
' | curl -fsS -c "$IGNIS_COOKIE" \
  -H 'Content-Type: application/json' \
  --data-binary @- \
  "$IGNIS_URL/api/auth/login"

# После успешного входа показать путь к cookie-файлу:
printf '%s\n' "$IGNIS_COOKIE"
```

## Обязательная редакционная проверка перед каждым деплоем Second Brain

Проверить целиком **все заметки, которые войдут в выпуск**, в обеих локалях, включая ранее опубликованные и навигационные. `draft: false` — необходимое условие, но не подтверждение готовности текста. Проверять не только поисковый индекс: читать текст, примеры, код, таблицы и содержимое изображений, затем смотреть собранные страницы.

- Искать пустые разделы, TODO, заглушки, напоминания автору, оборванные фразы и обещанные, но отсутствующие примеры.
- Проверять остатки диалога с ассистентом, обращения к неизвестному собеседнику, ссылки на неназванные материалы курса и служебные отчёты внутри статьи.
- Сверять примеры с объяснением: числа, формулы и код должны соответствовать тексту; таблицы и wikilinks должны корректно отображаться.
- В практических руководствах проверять достижение заявленного результата: текст не должен обрываться на ошибке без решения или явно обозначенной цели разбора.
- Не считать краткость саму по себе признаком черновика: законченные определения и навигационные каталоги допустимы; изображение может содержать полноценное объяснение.
- Для каждого подозрительного варианта представить пользователю ссылку и конкретную причину. До решения пользователя или согласованного исправления выпуск остановить. Не переписывать исходники и не менять `draft` самостоятельно.
- Это ручной редакционный шлюз: успешные автоматические тесты его не заменяют. До деплоя сохранить запись проверки всего состава и решений по исключениям с SHA-256 исходного manifest, карты пар и перечня хешей всех публикуемых RU/EN-файлов и вложений; без такой записи агент не запускает деплой. При изменении состава, исходников, любой локали, публичных преобразований или вложений повторить проверку и обновить запись. При снятии заметки исключить обе локали, маршруты, поиск, RSS, теги и карточки; ссылки на неё в публичных копиях заменить подписью, сохранив исходники Ignis.

## Подготовка и публикация

- Перед каждым деплоем проверьте **каждую заметку, попадающую в публикацию**: у файла в `content/ru/` должна быть полноценная английская версия в `content/en/` с тем же `translationKey`. Если версии нет, переведите заметку и добавьте файл до деплоя; незавершённый перевод (`translationPending`) не подходит.
- Сохраните существующий русский URL. Для английской заметки задайте осмысленное английское имя файла и slug под `/en/`. Обновите `docs/localization/published-baseline.json` и `localization/route-pairs.json` для новых опубликованных пар.
- При переводе сохраните все wikilinks и вложения: переводите подписи и при необходимости цели ссылок на соответствующие английские заметки, не теряя связей; оставляйте корректными пути к изображениям и другим файлам. Проверьте, что ссылки и вложения открываются в собранной английской версии.
- Перед деплоем запустите `npm run check:site`. Не деплойте сайт, пока для всех публикуемых заметок нет проверенных английских версий и не исправлены ошибки ссылок или вложений.

- При оформлении содержательных заметок соблюдайте [WRITING-STYLE.md](WRITING-STYLE.md): сохраняйте авторские формулировки, используйте существующие примеры и не дописывайте общие выводы ради шаблона. Навигационные заметки остаются каталогами ссылок.
