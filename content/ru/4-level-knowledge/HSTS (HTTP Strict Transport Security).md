> [!tldr] Коротко
> После первого защищённого соединения HSTS заставляет браузер сразу обращаться к сайту по HTTPS.

Версия заметки: **0.1 от 09.10.2026**

## Пример: два входа

Представим офис с двумя входами.

Первый вход - обычный, без проверки. Это HTTP.

Второй защищённый: с турникетом, охраной и пропуском. Это HTTPS.

Охранник может повесить на обычном входе табличку: «Пожалуйста, пройдите через защищённый вход». В вебе такую роль выполняет перенаправление с HTTP на HTTPS.

Если посетитель уже подошёл к незащищённому входу и успел открыть дверь, то есть вероятность, что его встретит злоумышленник и отправит человека не туда, куда он хотел.

HSTS помогает решить проблему: после посещения защищённого входа один раз браузер запоминает:

> Для этого адреса обычного входа не существует. Всегда используй только защищённый.

При следующем обращении браузер даже не пытается отправить HTTP-запрос. Он сразу использует HTTPS.

## Ограничение первого посещения

> [!warning]
> У HSTS есть ограничение: обычно браузер узнаёт о нём только после первого успешного HTTPS-соединения. Для защиты самого первого посещения существует [[HSTS Preload]], но это отдельное и гораздо более серьёзное решение. Добавлять `preload` «на всякий случай» нельзя, потому что тогда, если сертификат у домена истечет, то сайт станет недоступен, а быстро отменить настройку не получится

## Итого

Перенаправление ведёт с HTTP на HTTPS, а HSTS помогает браузеру не начинать следующий запрос с HTTP.
